# كيف ترفع الفيديو المرجعي (مقسّم إلى مقاطع)

## لماذا التقسيم؟
الفيديو الطويل/الثقيل لا يُرفع بسهولة على GitHub (حد 25MB من المتصفح، 100MB أقصى للـpush).
تقسيمه إلى مقاطع يحل المشكلة **ويعطيني دقة أعلى في التحليل**، لأن كل مقطع يُقرأ لوحده.

---

## ١. قسّم الفيديو (ffmpeg)

### تقسيم زمني (موصى به) — كل ٦٠ ثانية مقطع
```bash
ffmpeg -i wedding.mp4 -c copy -map 0 -segment_time 60 -f segment \
       -reset_timestamps 1 reference/part-%02d.mp4
```

### لو صيغة المصدر لا تسمح بالقص المباشر (mov من الآيفون مثلاً)
```bash
ffmpeg -i wedding.mov -vf "scale=-2:720" -c:v libx264 -crf 26 \
       -c:a aac -b:a 96k -segment_time 60 -f segment \
       -reset_timestamps 1 reference/part-%02d.mp4
```

### من الجوال بدون كمبيوتر
- **آيفون:** Photos → اختر الفيديو → Share → Save to Files → ثم قصّه من تطبيق Files، أو استخدم تطبيق **iMovie** وقسّمه لمشاريع ثم صدّر كل واحد.
- **أندرويد:** Google Photos → الفيديو → ⋮ → Trim، أو تطبيق **CapCut** → Split → Export لكل جزء.
- **أونلاين:** [8mb.video](https://8mb.video) أو [clideo.com/editor/split-video](https://clideo.com/editor/split-video) (تقسيم + ضغط).

## ٢. الرفع

### الطريقة أ — من المتصفح (لكل مقطع)
```
https://github.com/Shahd1982001/New_wedding_invetation/upload/main/reference
```
- اسحب **كل المقاطع مرة واحدة** (الصفحة تقبل عدة ملفات).
- تأكد: Branch = `main` · Folder = `reference`.
- Commit changes.

### الطريقة ب — من الطرفية (أسرع لكثير من المقاطع)
```bash
git clone https://github.com/Shahd1982001/New_wedding_invetation.git
cd New_wedding_invetation
mkdir -p reference && cp /path/to/part-*.mp4 reference/
git add reference/ && git commit -m "add reference video parts" && git push
```

### الطريقة ج — Release (لو مقطع واحد أكبر من 25MB)
Releases → New release → tag `reference-video` → اسحب الملفات → Publish → أرسل الروابط.

## ٣. قواعد التسمية (مهمة!)

الأداة ترتّب الملفات **رقمياً**، فالتسمية تحدّد ترتيب القصة:

| ✅ صحيح | ❌ خطأ |
|---|---|
| `part-01.mp4` | `part-1` ثم `part-10` ثم `part-2` |
| `part-02.mp4` | `مقطع أول.mp4` |
| `segment_01.mp4` | `video final new.mp4` |

استخدم **أرقام بخانتين** (`01`, `02`, …, `10`) وبادئة موحّدة، وحروف لاتينية بدون مسافات.

**نصيحة:** لا تقصّ في منتصف مشهد — اقطع عند انتقال طبيعي (تغيير مشهد/موسيقى) لو أمكن.

## ٤. ماذا أفعل أنا بعد الرفع

```bash
node tools/analyze-video.mjs reference/
```

الأداة:
1. تقرأ كل المقاطع **بالترتيب الصحيح**.
2. تستخرج إطارات كل ~١.٢ ثانية (بحد ٢٤ إطار/مقطع) بدقة 720px.
3. تحسب **التوقيت التراكمي** — أي مكان المقطع في الفيديو الكامل.
4. تلتقط الصوت من كل مقطع (لمقارنة الموسيقى والإيقاع).
5. تنتج `docs/video-analysis/report.json` + `notes.md` + `frames/part-XX/`.

ثم أفتح الإطارات وأقرأها واحدة واحدة، وأكتب تحليل مشهد بمشهد، وأعيد بناء الدعوة بنفس الأسلوب.

## ٥. حدود عملية

| العنصر | الحد |
|---|---|
| عدد المقاطع | بلا حد عملي (كل مقطع يُعالج لوحده) |
| حجم كل مقطع | **< 25MB** للرفع من المتصفح |
| مدة كل مقطع | ٣٠–٩٠ ثانية مثالي |
| دقة الفيديو | 720p كافية للتحليل؛ 1080p أفضل للخطوط |
| مجموع الفيديو | لو تجاوز ٣٠٠MB، ارفع الأجزاء المهمة فقط |

**لا تحتاج ترفع الفيديو كامل.** لو ١٠ دقائق، أرسل أول ٣ دقائق + المقطع اللي فيه الأسماء والتاريخ — وهذا يكفي لفهم الأسلوب.
